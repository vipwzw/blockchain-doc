# STARKs 重制版 Part I: 多项式的魔法
### —— 如何把"检查一百万次"变成"抽查一次"

### 1. 核心挑战：计算很脆弱，验证很昂贵

假设有人（证明者 Prover）声称他正确地运行了一个复杂的程序（比如计算 100 万步 Fibonacci 数列，或者验证一个区块链区块）。他想向你（验证者 Verifier）证明结果是对的。

*   **笨办法**：你把他的 100 万步重新算一遍。
    *   *缺点*：太慢，没有扩展性。
*   **稍微好点的办法**：让他把 100 万步的中间状态都发给你，你抽查几步。
    *   *致命缺陷*：**计算是极其脆弱的**。如果他在第 50 万步犯了一个极小的错误（把 0 写成 1），后续的所有结果都会错，但在这一步之前和之后的逻辑检查可能看起来是对的。如果你没刚好抽到那个错误点，你就被骗了。

**目标**：我们需要一种魔法，把"只在一个点出错"的坏计算，变成"在几乎所有点都出错"的形式。只有这样，**随机抽查**才能抓到坏人。

这种魔法就是 **多项式**。

---

### 2. 转化：把"约束"变成"多项式等式"

我们把这 100 万步计算的每一步状态，看作是一个多项式 $P(x)$ 在 $x=1, 2, ..., 10^6$ 处的取值。

#### 步骤 A: 写出约束
假设规则是简单的范围检查：每一步的值都必须在 0 到 9 之间。
$$0 \le P(x) \le 9, \quad \text{for } x = 1 \dots 10^6$$

#### 步骤 B: 变成代数零点 (Roots)
构造一个约束多项式 $C(y) = y(y-1)...(y-9)$。
如果 $P(x)$ 是合法的，那么 $C(P(x))$ **必须等于 0**。

#### 步骤 C: 变成整除问题 (Divisibility)
如果 $C(P(x))$ 在 $x = 1 \dots 10^6$ 上全是 0，根据代数定理，它一定能被零化多项式 $Z(x)$ 整除：
$$Z(x) = (x-1)(x-2)\dots(x-10^6)$$

于是，我们得到了一个**全局等式**：
$$C(P(x)) = Z(x) \cdot D(x)$$
*（其中 $D(x)$ 是整除后的商多项式）*

**现在的局面**：
为了证明那 100 万个点是对的，Prover 只需要证明：**存在两个多项式 $P(x)$ and $D(x)$，使得上面的等式对所有 $x$ 成立。**

---

### 3. 核心流程：承诺 → 抽查 → 验证

现在我们进入交互环节。为了防止作弊，我们必须遵循严格的顺序。

#### 第一步：承诺 (Commit)
Prover 把多项式 $P(x)$ 和 $D(x)$ 的值算出来，不仅算 $10^6$ 个点，而是算在一个更大的范围（比如 $10^9$ 个点）上。
他把这些值建成一个 **Merkle Tree**，把树根（Root）发给你。

```text
      [Merkle Root]  <-- Prover 此时已把数据锁死，无法抵赖
         /     \
      Hash    Hash
      /  \    /  \
    ...  ... ... ...
   /    \
 P(1)  P(2) ...       <-- 包含 P(x) 和 D(x) 的十亿个值
```
*   **为什么必须先承诺？**
    如果我不先让他把数据"锁"在 Merkle 树里，等我告诉他我要查哪个点，他就可以**临时编造**一个满足等式的值骗我。

#### 第二步：抽查 (Sample)
Verifier 抛出一个随机数 $x_{rand}$（范围在 $1 \dots 10^9$ 之间），向 Prover 发起挑战：
> "请告诉我 $P(x_{rand})$ 和 $D(x_{rand})$ 的值，并证明它们在树里。"

#### 第三步：验证 (Verify)
Prover 返回值和 Merkle 路径。Verifier 做两件事：
1.  **路径检查**：确认这些值确实属于刚才承诺的 Root。
2.  **代数检查**：计算 $C(P(x_{rand})) - Z(x_{rand}) \cdot D(x_{rand})$ 是否等于 0。

---

### 4. 深入理解：为什么树里必须同时有 P(x) 和 D(x)？

你可能注意到第一步"承诺"中说：Merkle 树包含 $P(x)$ **和** $D(x)$ 的值。这不是可选的，而是**必须的**。

#### 4.1 Verifier 不知道多项式的系数

Verifier 从不知道 $P(x)$ 或 $D(x)$ 的真正系数是什么。他只看到一个 Merkle Root。

当他在 $x_{rand}$ 处验证等式 $C(P(x_{rand})) = Z(x_{rand}) \cdot D(x_{rand})$ 时，他需要：
- $P(x_{rand})$ 的值 → 从 Merkle 树中读取
- $D(x_{rand})$ 的值 → **也必须从 Merkle 树中读取**
- $Z(x_{rand})$ 的值 → 可以自己计算（$Z$ 是公开的）

**如果树里只有 $P(x)$ 的值**，Verifier 就无法做等式验证！

#### 4.2 承诺结构

```text
                    [Merkle Root]
                    /           \
                  ...           ...
                 /                 \
   ┌─────────────────┐    ┌─────────────────┐
   │ P(1), D(1)      │    │ P(2), D(2)      │   ...
   │ 在位置 1 的值   │    │ 在位置 2 的值   │
   └─────────────────┘    └─────────────────┘
```

每个叶子节点包含**一对值**：$(P(x_i), D(x_i))$。

Prover 承诺后就无法修改。当 Verifier 抽查 $x_{rand}$ 时：
1. Prover 返回 $(P(x_{rand}), D(x_{rand}))$ 和对应的 Merkle 路径
2. Verifier 验证路径正确（值没被篡改）
3. Verifier 计算 $C(P(x_{rand})) \stackrel{?}{=} Z(x_{rand}) \cdot D(x_{rand})$

---

### 5. 为什么无法伪造？（从多项式的来源理解）

你可能会问：*"证明者能不能用一个假的多项式 $Q(x)$ 来骗我？验证者怎么知道这个多项式是'正确计算'对应的那个？"*

#### 5.1 多项式从哪里来？——来自电路/计算轨迹

多项式 $P(x)$ **不是随便选的**，它是**计算轨迹的编码**。在实际系统中，计算问题首先被编译成算术电路，然后电路的执行轨迹被编码为多项式。

```text
┌─────────────────────────────────────────────────────────────────────┐
│  例子：证明 Fibonacci 数列的第 100 万项                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  计算轨迹（来自电路执行）：                                         │
│  ────────────────────────                                           │
│  F(1) = 0                                                           │
│  F(2) = 1                                                           │
│  F(3) = F(1) + F(2) = 1                                            │
│  F(4) = F(2) + F(3) = 2                                            │
│  ...                                                                │
│  F(10^6) = 某个巨大的数                                             │
│                                                                     │
│  编码为多项式：                                                     │
│  ────────────                                                       │
│  P(1) = 0, P(2) = 1, P(3) = 1, P(4) = 2, ...                       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 5.2 约束多项式 C 编码了完整的计算规则

关键点：$C$ 不仅仅是"范围检查"，它编码了**电路的所有约束**！

```text
┌─────────────────────────────────────────────────────────────────────┐
│  Fibonacci 电路的完整约束（都被编码进 C）：                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ① 边界条件：P(1) = 0, P(2) = 1                                    │
│     → 如果 P(1) ≠ 0，则 C(P(1)) ≠ 0                               │
│                                                                     │
│  ② 递推关系：P(x+2) = P(x+1) + P(x)  对于 x = 1, 2, ..., 10^6-2   │
│     → 如果某步递推错误，则 C(P(x)) ≠ 0                            │
│                                                                     │
│  ③ 输出声明：P(10^6) = claimed_result                              │
│     → 如果输出不对，则 C(P(10^6)) ≠ 0                             │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 5.3 假多项式为什么无法通过验证？

假设 Prover 想作弊，用一个假多项式 $Q(x)$（对应一个错误的计算轨迹）：

| 作弊方式 | 对应的电路错误 | 会发生什么 |
|---------|---------------|-----------|
| $Q$ 不满足边界条件 | 初始值错误 | $C(Q(1)) \ne 0$ 或 $C(Q(2)) \ne 0$ |
| $Q$ 不满足递推关系 | 某步计算错误 | 某些 $x$ 处 $C(Q(x)) \ne 0$ |
| $Q$ 输出错误结果 | 最终答案错误 | $C(Q(10^6)) \ne 0$ |

**核心逻辑链**：
$$\text{错误的计算} \xrightarrow{\text{编码}} \text{假多项式 Q} \xrightarrow{\text{不满足电路约束}} C(Q(x)) \ne Z(x) \cdot D(x)$$

#### 5.4 错误放大效应

如果 $Q(x)$ 哪怕只在**一步**计算上出错（比如第 50 万步），等式 $C(Q(x)) = Z(x) \cdot D(x)$ 就会在**绝大多数点**上不成立。

*   **数学原理**：两个不同的 $N$ 次多项式，最多只有 $N$ 个交点。
*   在 $10^9$ 个点中，最多 $10^7$ 个点"碰巧"相等
*   随机抽一个点，99% 以上概率发现错误

**结论**：证明者无法用假多项式（错误计算）欺骗验证者，因为：
1. 约束 $C$ 完整编码了电路的计算规则
2. 任何错误的计算轨迹对应的 $Q(x)$，都不满足电路约束
3. 不满足约束 = 等式不成立 = 随机抽查几乎必然发现

### 6. 关键问题：$x > 10^6$ 时，$P(x)$ 还在 0-9 范围内吗？

**答案是：不一定！但没关系！**

这是一个常见的困惑点。原始约束 $0 \le P(x) \le 9$ **只在** $x = 1 \dots 10^6$ 范围内有业务意义。当 $x > 10^6$ 时，$P(x)$ 的值可能是 100、1000 或任意数。

#### 6.1 语义约束 vs 多项式恒等式

| 概念 | 适用范围 | 说明 |
|-----|---------|------|
| **语义约束** | $x = 1 \dots 10^6$ | "每步的值必须在 0-9" |
| **多项式恒等式** | 所有 $x$ | $C(P(x)) = Z(x) \cdot D(x)$ |

**Verifier 验证的是多项式恒等式，不是语义约束！**

如果等式 $C(P(x)) = Z(x) \cdot D(x)$ 作为**多项式**成立（即左右两边的系数完全相同），那么代入**任何** $x$ 值，数值等式都成立——包括 $x > 10^6$ 的点！

#### 6.2 具体例子

```text
┌─────────────────────────────────────────────────────────────────────┐
│  x = 5 （在约束域内）                                                │
│  ─────────────────────                                              │
│  P(5) = 3        （假设值为 3，在 0-9 范围内）                       │
│  C(P(5)) = C(3) = 0    ✓                                            │
│  Z(5) = 0              （因为 5 是 Z 的根）                          │
│  等式: 0 = 0 · D(5)    ✓ 成立                                       │
│                                                                     │
├─────────────────────────────────────────────────────────────────────┤
│  x = 2×10^6 （在约束域外）                                          │
│  ─────────────────────────                                          │
│  P(2×10^6) = 12345     （可能是任意值，不受 0-9 限制！）            │
│  C(P(2×10^6)) = C(12345) = 很大的数                                 │
│  Z(2×10^6) = 也是很大的数（不为零）                                 │
│  等式: C(12345) = Z(2×10^6) · D(2×10^6)   ✓ 仍然成立！              │
│                                                                     │
│  → P(x) 不在 0-9 范围内，但多项式等式仍然成立                       │
└─────────────────────────────────────────────────────────────────────┘
```

#### 6.3 为什么这样设计是安全的？

多项式恒等式成立 ⟹ 语义约束在 $1 \dots 10^6$ 上成立。

**逻辑链条：**
1. 如果 $C(P(x)) = Z(x) \cdot D(x)$ 对所有 $x$ 成立
2. 那么在 $x = k$（$k \in 1 \dots 10^6$）处：$Z(k) = 0$
3. 所以 $C(P(k)) = 0$
4. 所以 $P(k) \in \{0, 1, ..., 9\}$ ✓

这就是为什么可以在 $10^9$ 范围内随机抽样——我们验证的是**多项式恒等式**，它隐含了原始约束！

# STARKs 重制版 Part II: 警察来了 (FRI)
### —— 为什么必须证明是"低度"多项式？

### 1. Part I 留下的致命漏洞

在 Part I 中，我们假设 Prover 承诺的那个表，真的来自一个多项式 $P(x)$。
但是，如果有极端的恶意攻击者：
他**根本不用多项式**！他针对每一个 $x$，都临时算出一对 $P_{fake}$ 和 $D_{fake}$，让它们**刚好满足**那个等式 $C(P) = Z \cdot D$。
因为他不是用多项式生成的点，而是逐点凑出来的，所以"多项式交点有限"的定理失效了！

**必须引入警察**：我们需要一种方法证明 Prover 承诺的那张表，**确实来自一个低次数（Low Degree）多项式**。这就是 **FRI** 协议。

---

### 2. 为什么必须是"低度"的？

*   **低度 = 信息量受限**。
    一个 100 万次的多项式，只有 100 万个自由度。如果你给了我 10 亿个点，它们之间是高度相关的，不能随便乱填。
*   **高度/无度 = 混乱**。
    如果允许高度数或非多项式，Prover 可以在关键位置填"正确数据"，在抽查位置填"作弊数据"，完全不受数学规律束缚。

**STARK 的核心安全逻辑**：
> 只有当数据是**低度多项式**时，抽样验证才是可靠的。

---

### 3. 关键问题：为什么不能用另一个多项式 Q(x) 来骗过等式检查？

你可能会问：*"既然只要满足 $C(P(x)) = Z(x) \cdot D(x)$ 就行，我能不能找另一个多项式 $Q(x)$，也满足 $C(Q(x)) = Z(x) \cdot G(x)$？"*

**答案是：可以！但会被低度测试抓住。**

#### 3.1 用拉格朗日插值作弊

假设约束域是 $x = 1 \dots 10^6$，要求 $P(x) \in \{0, ..., 9\}$。

作弊方法：随便选 100 万个值 $v_1, v_2, ..., v_{10^6}$，每个都在 0-9 范围内。然后用**拉格朗日插值**构造一个多项式 $Q(x)$，使得 $Q(i) = v_i$。

```text
┌─────────────────────────────────────────────────────────────────────┐
│                     拉格朗日插值作弊                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  选择任意值（都在 0-9 范围内）：                                    │
│  v₁ = 3, v₂ = 7, v₃ = 2, ..., v_{10^6} = 5                         │
│                                                                     │
│  用拉格朗日插值构造：                                               │
│                 10^6                                                │
│  Q(x) = Σ  vᵢ · Lᵢ(x)                                              │
│                i=1                                                  │
│                                                                     │
│  结果：                                                             │
│  ✓ Q(1) = 3, Q(2) = 7, ... 都在 0-9 范围内                         │
│  ✓ 满足等式 C(Q(x)) = Z(x) · G(x)                                  │
│  ✗ 但 deg(Q) = 10^6 - 1 ！！！（非常高）                           │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 3.2 低度测试排除这种攻击

真实的 $P(x)$ 应该是一个**低度多项式**（比如度数 $d \ll 10^6$）。

| 多项式 | 度数 | 能否满足范围约束 | 能否通过低度测试 |
|-------|------|-----------------|-----------------|
| 真实的 $P(x)$ | $d \approx 10^3$ | ✓ | ✓ |
| 作弊的 $Q(x)$ (插值) | $10^6 - 1$ | ✓ | ✗ **失败！** |

**关键洞察**：
- 一个度数为 $d$ 的多项式，只有 $d+1$ 个自由参数
- 它必须同时满足 $10^6$ 个约束点
- $d$ 个参数 vs $10^6$ 个约束 → **极度过约束**
- 几乎只有唯一的多项式能同时满足

**FRI 做两件事：**
1. **等式验证**：$C(P(x)) = Z(x) \cdot D(x)$
2. **低度测试**：$\deg(P) \le d$

两者结合，才能保证安全！

---

### 4. FRI 的核心机制：递归折叠

要证明一个海量数据集（10亿点）来自低度多项式，我们不能全读一遍。我们要用 **递归折半** 的方法。

#### 核心思想：把"度"减半
假设 Prover 声称 $f(x)$ 的次数小于 $D$。
我们可以把 $f(x)$ 拆成偶数项和奇数项：
$$f(x) = g(x^2) + x \cdot h(x^2)$$
这里 $g$ 和 $h$ 的次数都只有 $D/2$。

Verifier 发送一个随机数 $\alpha$，Prover 将两部分折叠成一个新的多项式：
$$f_{new}(y) = g(y) + \alpha \cdot h(y)$$
这个新多项式 $f_{new}$ 的次数是原来的一半 ($D/2$)。

#### 递归过程
1.  **开始**：我有一列数据，声称来自次数 < $D$ 的多项式。
2.  **折叠**：Verifier 给出随机数，Prover 把这列数据"折叠"成长度减半、次数上限减半的新列。
3.  **重复**：$D \to D/2 \to D/4 \dots$ 直到次数变成常数（比如 < 2，即直线）。
4.  **终局**：对于最后剩下的那几个数，Verifier 直接看一眼：它们在一条直线上吗？

```text
[原始数据 10亿点]  <-- 声称次数 < 1,000,000
       |
       | (随机折叠)
       v
[第1层数据 5亿点]  <-- 此时应 < 500,000
       |
       | (随机折叠)
       v
      ...
       v
[第20层数据]      <-- 此时应 < 1 (常数)
```

---

### 5. 为什么无法伪造？（深度与一致性）

你可能会问：*"如果 Prover 一开始就是个高次多项式（比如 10亿次），他能不能骗过 FRI？"*

**不能，原因如下：**

1.  **随机性的力量**：
    在折叠公式 $f_{new} = g + \alpha \cdot h$ 中，由于 $\alpha$ 是 Verifier 随机选的，Prover 无法提前安排 $g$ 和 $h$ 来让它们在折叠后恰好变成低次多项式（除非运气好到中彩票）。高次成分会被保留下来。

2.  **递归的"照妖镜"**：
    递归树的高度是由**声称的次数 $D$** 决定的（比如 $D=10^6$，树高 20 层）。
    *   如果 Prover 实际用的是 $10^9$ 次的多项式。
    *   折叠 20 次后，理论上多项式应该变成常数了。
    *   但实际上，由于起始次数太高，折叠 20 次后，它依然是一个很高次的多项式（或者完全是噪声）。
    *   **终局验证**时，Verifier 会发现剩下的点根本不在一条直线上 → **抓住了！**

3.  **层间抽查**：
    除了看终局，Verifier 还会随机抽查"上一层"和"下一层"的数据是否满足折叠公式。如果 Prover 试图在中间层作假（直接换成一个新的低次多项式），数学关系就会对不上。

### 6. 总结

*   **Part I** 告诉我们：只要是多项式，**抽查一个点**就能验证整个计算是否正确。
*   **Part II** 告诉我们：FRI 可以保证 Prover 承诺的数据**确实是低度多项式**。

两者结合，Verifier 只需要极其微小的计算量（对数级），就能通过数学保证，相信 Prover 确实完成了那海量的计算任务。这就是 **zk-STARK** 的力量。
