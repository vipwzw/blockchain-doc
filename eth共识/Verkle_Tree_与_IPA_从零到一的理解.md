## 第一章：单值承诺——隐藏一个数

在密码学中，**承诺（Commitment）** 是一种基础原语：我先把一个值"锁"起来，之后可以证明这个值确实是我之前锁定的那个。

### 1.1 哈希承诺

最简单的承诺方式是使用哈希函数：

```
┌─────────────────────────────────────────────────────────────────────┐
│                         哈希承诺                                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   承诺阶段:                                                         │
│   ──────────                                                        │
│   给定值 v = 42                                                     │
│   计算承诺 C = H(v) = H(42)                                        │
│   公开 C                                                            │
│                                                                     │
│   打开阶段:                                                         │
│   ──────────                                                        │
│   公开 v = 42                                                       │
│   验证者检验 H(v) == C ?                                           │
│                                                                     │
│   性质:                                                             │
│   • 绑定性: 无法找到另一个 v' 使得 H(v') = C                       │
│   • 隐藏性: 从 C 无法反推 v（单向性）                               │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.2 Pedersen 承诺

Pedersen 承诺使用椭圆曲线，提供了更强的数学性质：

```
┌─────────────────────────────────────────────────────────────────────┐
│                       Pedersen 承诺                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   设置:                                                             │
│   ──────                                                            │
│   选择椭圆曲线群 G，两个独立生成元 G, H                             │
│   （没有人知道 log_G(H)）                                           │
│                                                                     │
│   承诺阶段:                                                         │
│   ──────────                                                        │
│   给定值 v = 42，选择随机盲因子 r                                  │
│   计算承诺 C = v·G + r·H                                           │
│   公开 C                                                            │
│                                                                     │
│   打开阶段:                                                         │
│   ──────────                                                        │
│   公开 (v, r)                                                       │
│   验证者检验 v·G + r·H == C ?                                      │
│                                                                     │
│   额外性质:                                                         │
│   • 同态性: C(v₁) + C(v₂) = C(v₁ + v₂)                             │
│   • 完美隐藏: 即使有无限计算能力也无法从 C 推出 v                  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.3 两种承诺的对比

| 特性 | 哈希承诺 H(v) | Pedersen 承诺 v·G + r·H |
|------|---------------|-------------------------|
| 计算效率 | 快（哈希运算） | 慢（椭圆曲线运算） |
| 承诺大小 | 32 bytes | 32 bytes（压缩点） |
| 同态性 | ✗ 无 | ✓ 有 |
| 隐藏性 | 计算性隐藏 | 完美隐藏 |

**关键洞察**：对于单个值，两种承诺在大小上没有区别。但 Pedersen 承诺的**同态性**将在后续发挥关键作用。

## 第二章：向量承诺——隐藏一组数

现在我们扩展到向量：如何承诺一个包含 n 个值的向量 \( \mathbf{v} = [v_0, v_1, \dots, v_{n-1}] \) ？

### 2.1 方案一：Merkle Tree（哈希向量承诺）

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Merkle Tree 作为向量承诺                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   向量: v = [v₀, v₁, v₂, v₃, v₄, v₅, v₆, v₇]                       │
│                                                                     │
│   构建二叉 Merkle Tree:                                             │
│                                                                     │
│                              [Root]                                 │
│                             /      \                                │
│                         [H₀₃]      [H₄₇]                            │
│                        /    \      /    \                           │
│                     [H₀₁] [H₂₃] [H₄₅] [H₆₇]                        │
│                     / \   / \   / \   / \                           │
│                   [L₀][L₁][L₂][L₃][L₄][L₅][L₆][L₇]                  │
│                    ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑                    │
│                   H(v₀) ... ... ... ... ... ... H(v₇)               │
│                                                                     │
│   承诺 = Root（单个 32 bytes 的哈希值）                            │
│                                                                     │
│   证明位置 i 的值:                                                  │
│   提供从叶子到根的路径上所有兄弟节点的哈希                          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**证明大小**：对于 n = 256 个叶子的二叉树
\[ \text{证明大小} = \log_2(256) \times 32 = 8 \times 32 = 256 \text{ bytes} \]

### 2.2 方案二：Pedersen 向量承诺

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Pedersen 向量承诺                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   设置:                                                             │
│   ──────                                                            │
│   选择 n 个独立生成元 G₀, G₁, ..., Gₙ₋₁                             │
│                                                                     │
│   向量: v = [v₀, v₁, v₂, ..., vₙ₋₁]                                │
│                                                                     │
│   计算承诺:                                                         │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   C = v₀·G₀ + v₁·G₁ + v₂·G₂ + ... + vₙ₋₁·Gₙ₋₁              │  │
│   │                                                             │  │
│   │   或简写为: C = ⟨v, G⟩ = Σᵢ vᵢ·Gᵢ                           │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
│   承诺 = C（单个 32 bytes 的群元素）                               │
│                                                                     │
│   问题: 如何证明位置 i 的值是 vᵢ ？                                │
│   这就是 IPA 要解决的问题!                                          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 两种向量承诺的对比

| 特性 | Merkle Tree | Pedersen 向量承诺 |
|------|-------------|-------------------|
| 承诺大小 | 32 bytes（根哈希） | 32 bytes（群元素） |
| 单个位置证明 (n=256) | **256 bytes** ✓ | 需要 IPA |
| 更新一个值 | O(log n) 次哈希 | O(1) 次群运算 |
| 同态性 | ✗ 无 | ✓ 有 |

**关键发现**：对于**单个位置**的证明，二叉 Merkle Tree 只需要 256 bytes，非常紧凑！

那为什么还需要 Pedersen 向量承诺和 IPA 呢？答案在于**批量证明**和**聚合能力**。

## 第三章：位置证明——证明某个位置的值

假设我们要证明"位置 5 的值是 42"。

### 3.1 Merkle Tree 的位置证明

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Merkle 位置证明 (位置 5，值 42)                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   向量: [10, 20, 30, 40, 50, 42, 60, 70]                           │
│   索引:   0   1   2   3   4   5   6   7                            │
│                                                                     │
│   位置 5 的二进制: 101 → 路径: 右-左-右                            │
│                                                                     │
│                              [Root]                                 │
│                             /      \                                │
│                      [H₀₃]─────────[H₄₇]    ← 需要 H₀₃             │
│                      (兄弟)       /      \                          │
│                               [H₄₅]─────[H₆₇]  ← 需要 H₆₇          │
│                               /    \    (兄弟)                      │
│                           [L₄]────[L₅]         ← 需要 L₄           │
│                          (兄弟)   H(42)                             │
│                                     ↑                               │
│                                  目标叶子                           │
│                                                                     │
│   证明内容:                                                         │
│   proof = [L₄, H₆₇, H₀₃]   (3 个兄弟哈希)                          │
│                                                                     │
│   验证过程:                                                         │
│   1. h₀ = H(42)                                                     │
│   2. h₁ = H(L₄ || h₀)       // L₄ 在左                             │
│   3. h₂ = H(h₁ || H₆₇)      // H₆₇ 在右                            │
│   4. h₃ = H(H₀₃ || h₂)      // H₀₃ 在左                            │
│   5. 检验: h₃ == Root ?                                            │
│                                                                     │
│   证明大小: 3 × 32 = 96 bytes                                      │
│   对于 n=256: 8 × 32 = 256 bytes                                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.1.1 背景知识：二进制编码与 Merkle 路径的对应关系

在验证 Merkle 证明时，验证者需要知道每一层应该把"当前哈希"放在左边还是右边。这个信息直接由**位置的二进制编码**决定：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    二进制编码 = 路径方向                             │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   核心原理:                                                         │
│   ──────────                                                        │
│   在完全二叉树中，每个节点的位置可以用二进制编码唯一确定。          │
│   二进制的每一位对应树的一层：                                      │
│   • 0 = 走左子树 (当前节点在父节点的左边)                          │
│   • 1 = 走右子树 (当前节点在父节点的右边)                          │
│                                                                     │
│   示例: 8 个叶子的树 (深度 3)                                       │
│   ────────────────────────────                                      │
│                                                                     │
│   位置   二进制   路径                                              │
│   ────   ──────   ─────────────────────────────                     │
│     0    000      左 → 左 → 左                                      │
│     1    001      左 → 左 → 右                                      │
│     2    010      左 → 右 → 左                                      │
│     3    011      左 → 右 → 右                                      │
│     4    100      右 → 左 → 左                                      │
│     5    101      右 → 左 → 右                                      │
│     6    110      右 → 右 → 左                                      │
│     7    111      右 → 右 → 右                                      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    位置 5 (二进制 101) 的路径图解                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   从高位到低位读取 101:                                             │
│   第 1 位 = 1 → 从根走右                                           │
│   第 2 位 = 0 → 走左                                               │
│   第 3 位 = 1 → 走右，到达叶子                                     │
│                                                                     │
│                           [Root]                                    │
│                          /      \                                   │
│                        ↙          ↘  ← 第1位=1，走右               │
│                     [H₀₃]        [H₄₇]                              │
│                                 /      \                            │
│                               ↙          ↘  ← 第2位=0，走左        │
│                            [H₄₅]        [H₆₇]                       │
│                           /      \                                  │
│                         ↙          ↘  ← 第3位=1，走右              │
│                      [L₄]          [L₅] ← 到达位置 5!              │
│                                                                     │
│   验证时哈希计算顺序:                                               │
│   ─────────────────────                                             │
│   从叶子往上计算，二进制位决定拼接顺序：                            │
│   • 第3位=1 (右): h₁ = H(L₄ || H(42))     // 我在右边，兄弟在左   │
│   • 第2位=0 (左): h₂ = H(h₁ || H₆₇)       // 我在左边，兄弟在右   │
│   • 第1位=1 (右): h₃ = H(H₀₃ || h₂)       // 我在右边，兄弟在左   │
│                                                                     │
│   规则: 当前位=0 → H(当前 || 兄弟)                                 │
│         当前位=1 → H(兄弟 || 当前)                                 │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**验证算法的伪代码**：

```python
def verify_merkle_proof(root, index, value, siblings):
    """
    验证 Merkle 证明
    
    Args:
        root: 已知的 Merkle 根
        index: 声称的位置 (e.g., 5)
        value: 声称的值 (e.g., 42)
        siblings: 兄弟节点哈希列表 [L₄, H₆₇, H₀₃]
    """
    current_hash = H(value)
    
    for i, sibling in enumerate(siblings):
        # 取 index 的第 i 位 (从低位开始)
        bit = (index >> i) & 1
        
        if bit == 0:
            # 当前节点在左边
            current_hash = H(current_hash || sibling)
        else:
            # 当前节点在右边
            current_hash = H(sibling || current_hash)
    
    return current_hash == root
```

> 💡 **关键点**：验证者声称要验证"位置 5 的值是 42"，位置 5 本身就是声明的一部分。验证者根据位置 5 的二进制编码 `101` 来决定哈希的拼接顺序。如果攻击者提供的 proof 是其他位置的兄弟哈希，按照位置 5 的路径计算将无法得到正确的 Root。

### 3.2 向量承诺的位置证明：内积视角

Pedersen 向量承诺如何做位置证明？关键是将"位置查询"转化为"内积计算"：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    位置证明 = 内积证明                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   核心洞察:                                                         │
│   ──────────                                                        │
│   构造"选择器向量" e，其中只有位置 i 为 1，其余为 0                │
│                                                                     │
│   例如，要证明位置 5 的值:                                          │
│   e = [0, 0, 0, 0, 0, 1, 0, 0]                                     │
│                       ↑                                             │
│                    位置 5                                           │
│                                                                     │
│   那么:                                                             │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   ⟨v, e⟩ = v₀·0 + v₁·0 + ... + v₅·1 + ... + v₇·0 = v₅      │  │
│   │                                                             │  │
│   │   内积结果 = 位置 5 的值!                                   │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
│   问题转化:                                                         │
│   ──────────                                                        │
│   原问题: 证明 "位置 5 的值是 42"                                  │
│   新问题: 证明 "⟨v, e⟩ = 42"，其中 C = ⟨v, G⟩ 是公开的承诺        │
│                                                                     │
│   这就是 IPA (Inner Product Argument) 要解决的问题!                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.3 IPA 的证明大小

对于 n = 256：
\[ \text{IPA 证明大小} = 2 \times \log_2(256) \times 32 + 32 = 16 \times 32 + 32 = 544 \text{ bytes} \]

### 3.4 KZG 多项式承诺：O(1) 的证明大小

除了 Merkle Tree 和 IPA，还有第三种方案：**KZG (Kate-Zaverucha-Goldberg) 多项式承诺**。

```
┌─────────────────────────────────────────────────────────────────────┐
│                    KZG 多项式承诺原理                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   核心思想:                                                         │
│   ──────────                                                        │
│   将向量 v = [v₀, v₁, ..., vₙ₋₁] 编码为多项式:                     │
│                                                                     │
│   P(X) = v₀ + v₁·X + v₂·X² + ... + vₙ₋₁·Xⁿ⁻¹                       │
│                                                                     │
│   或使用拉格朗日插值:                                               │
│   P(ωⁱ) = vᵢ，其中 ω 是 n 次单位根                                 │
│                                                                     │
│   位置证明变成了多项式求值证明:                                     │
│   "位置 i 的值是 42" ⟺ "P(ωⁱ) = 42"                                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    KZG 承诺与证明                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   可信设置 (Trusted Setup):                                         │
│   ─────────────────────────                                         │
│   生成公共参数: [G, τ·G, τ²·G, ..., τⁿ⁻¹·G]                        │
│   其中 τ 是秘密值，设置后必须销毁                                   │
│                                                                     │
│   承诺:                                                             │
│   ──────                                                            │
│   C = P(τ)·G = (v₀ + v₁τ + v₂τ² + ...)·G                           │
│                                                                     │
│   由于没人知道 τ，这是用公共参数计算的:                            │
│   C = v₀·G + v₁·(τG) + v₂·(τ²G) + ...                              │
│                                                                     │
│   证明位置 i 的值:                                                  │
│   ─────────────────                                                 │
│   要证明 P(ωⁱ) = vᵢ                                                │
│                                                                     │
│   构造商多项式: Q(X) = [P(X) - vᵢ] / (X - ωⁱ)                      │
│   （如果 P(ωⁱ) = vᵢ，则 (X - ωⁱ) 整除 P(X) - vᵢ）                 │
│                                                                     │
│   证明 = π = Q(τ)·G                                                │
│                                                                     │
│   验证 (使用配对):                                                  │
│   ─────────────────                                                 │
│   e(C - vᵢ·G, G) = e(π, τ·G - ωⁱ·G)                                │
│                                                                     │
│   证明大小 = 1 个群元素 = 48 bytes (BLS12-381)                     │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    KZG 的代价                                        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   优点:                                                             │
│   ──────                                                            │
│   • 证明大小: O(1) = 48 bytes ← 非常小!                            │
│   • 验证时间: O(1) = 2 次配对运算                                  │
│   • 批量证明: 多个证明可以聚合为一个                               │
│                                                                     │
│   代价:                                                             │
│   ──────                                                            │
│   • 需要可信设置 (Trusted Setup)                                   │
│     - 必须有仪式来生成公共参数                                     │
│     - 参与者必须诚实销毁 τ                                         │
│     - 如果 τ 泄露，整个系统不安全                                  │
│                                                                     │
│   • 公共参数大小: O(n)                                             │
│     - 需要存储 [G, τG, τ²G, ..., τⁿ⁻¹G]                            │
│     - n = 256 时: 256 × 48 = 12 KB                                 │
│     - n = 2²⁰ 时: ~50 MB                                           │
│                                                                     │
│   • 不抗量子攻击                                                   │
│     - 基于椭圆曲线配对，量子计算机可破解                           │
│     - 升级到后量子方案更困难                                       │
│                                                                     │
│   • 证明生成较慢                                                   │
│     - 需要 O(n) 次群运算来计算商多项式的承诺                       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.5 三种方案对比

**比较**（n = 256 的单点证明）：

| 方案 | 证明大小 | 可信设置 | 公共参数 |
|------|----------|----------|----------|
| 二叉 Merkle Tree | 256 bytes | 不需要 | O(1) |
| IPA | 544 bytes | 不需要 | O(n) |
| **KZG** | **48 bytes** ✓ | **需要** | O(n) |

**等等，KZG 最小，为什么以太坊选择 IPA？**

答案在于：**可信设置的风险** 和 **批量证明的综合考量**。

### 4.2 批量证明场景：IPA 逆袭

但现实中，我们需要**同时证明多个位置**的值。这就是 IPA 的聚合能力发挥作用的地方：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    批量证明场景 (n = 256, k 个位置)                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   Merkle Tree 批量证明:                                             │
│   ─────────────────────                                             │
│   每个证明是独立的，最多只能共享部分路径                            │
│   最坏情况: k × 256 bytes                                          │
│   最好情况: 取决于路径重叠程度                                      │
│                                                                     │
│   IPA 批量证明 (聚合!):                                             │
│   ─────────────────────                                             │
│   k 个位置的证明可以聚合成一个!                                     │
│                                                                     │
│   方法: 用随机线性组合构造聚合选择器                                │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   e_agg = r₁·e_{i₁} + r₂·e_{i₂} + ... + rₖ·eᵢₖ             │  │
│   │                                                             │  │
│   │   其中 rⱼ 是随机系数，eᵢⱼ 是位置 iⱼ 的单位向量              │  │
│   │                                                             │  │
│   │   聚合内积:                                                 │  │
│   │   ⟨v, e_agg⟩ = r₁·vᵢ₁ + r₂·vᵢ₂ + ... + rₖ·vᵢₖ              │  │
│   │                                                             │  │
│   │   只需要一个 IPA 证明来验证这个聚合内积!                    │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
│   聚合证明大小 ≈ 544 + k × 32 bytes (每个值需要 32 bytes)          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    KZG 批量证明                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   KZG 也支持批量证明聚合:                                           │
│   ─────────────────────────                                         │
│                                                                     │
│   方法: 随机线性组合多个求值证明                                    │
│                                                                     │

│   KZG 略优于 IPA，但差距不大!                                       │

### 4.2.1 为什么必须是"随机"线性组合？

这个"随机"不是可选的装饰，而是安全性的核心保障。

```
┌─────────────────────────────────────────────────────────────────────┐
│                    问题：直接求和的安全漏洞                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   假设我们不用随机系数，直接把多个位置的值加起来验证：              │
│                                                                     │
│   证明者声称:                                                       │
│   • 位置 3 的值是 v₃ = 100                                         │
│   • 位置 7 的值是 v₇ = 50                                          │
│   • 总和 = 150                                                      │
│                                                                     │
│   攻击场景:                                                         │
│   实际值可能是 v₃ = 80, v₇ = 70，总和也是 150！                    │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   只验证 v₃ + v₇ = 150 无法区分：                          │  │
│   │                                                             │  │
│   │   (100, 50) ← 声称的值                                     │  │
│   │   (80, 70)  ← 真实的值                                     │  │
│   │   (150, 0)  ← 另一种伪造                                   │  │
│   │   ...                                                       │  │
│   │                                                             │  │
│   │   无穷多种组合的和都是 150！                                │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    解决方案：随机线性组合                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   使用随机系数 r₁, r₂ 进行聚合:                                    │
│                                                                     │
│   聚合值 = r₁·v₃ + r₂·v₇                                           │
│                                                                     │
│   关键: r₁, r₂ 是在证明者提交承诺之后才生成的！                    │
│   （通过 Fiat-Shamir 变换，由承诺的哈希值确定）                    │
│                                                                     │
│   攻击者的困境:                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   假设真实值是 (v₃, v₇) = (80, 70)                         │  │
│   │   攻击者声称   (v₃', v₇') = (100, 50)                       │  │
│   │                                                             │  │
│   │   如果 r₁·100 + r₂·50 = r₁·80 + r₂·70                      │  │
│   │   则    r₁·20 = r₂·20                                       │  │
│   │   即    r₁ = r₂                                             │  │
│   │                                                             │  │
│   │   但 r₁, r₂ 是随机的，r₁ = r₂ 的概率约为 1/q               │  │
│   │   (q 是群的阶，约为 2²⁵⁶，概率可忽略不计)                   │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**数学原理：Schwartz-Zippel 引理的完整推导**

首先明确各个角色：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    变量角色分析                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   固定值（由承诺 C 绑定，攻击者提交后无法更改）:                   │
│   ──────────────────────────────────────────────                    │
│   • v₃, v₇ = 真实值（被承诺绑定）                                  │
│   • 这些值在承诺 C 提交时就已经确定                                │
│                                                                     │
│   攻击者声称的值（谎言）:                                          │
│   ──────────────────────                                            │
│   • v₃', v₇' = 攻击者对外声称的值                                  │
│   • 这些值可能与真实值不同                                         │
│                                                                     │
│   随机变量（验证者在承诺后生成）:                                  │
│   ────────────────────────────────                                  │
│   • r₁, r₂ = 随机聚合系数                                          │
│   • 由 Fiat-Shamir 变换从承诺 C 派生                               │
│   • 攻击者在提交承诺时无法预测                                     │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    攻击成功的条件分析                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   验证过程:                                                         │
│   ──────────                                                        │
│   1. 攻击者声称: "位置 3 的值是 v₃'=100，位置 7 的值是 v₇'=50"    │
│   2. 验证者计算聚合选择器: e_agg = r₁·e₃ + r₂·e₇                  │
│   3. 验证者期望的聚合内积: z' = r₁·v₃' + r₂·v₇' = r₁·100 + r₂·50 │
│   4. IPA 验证: 检查 ⟨v, e_agg⟩ = z' ？                            │
│                                                                     │
│   但 IPA 验证会使用承诺 C 中绑定的真实向量 v！                     │
│   真实的内积是: ⟨v, e_agg⟩ = r₁·v₃ + r₂·v₇ = r₁·80 + r₂·70       │
│                                                                     │
│   攻击成功 ⟺ 验证者期望值 = 真实内积                              │
│   ──────────────────────────────────────                            │
│   r₁·v₃' + r₂·v₇' = r₁·v₃ + r₂·v₇                                 │
│                                                                     │
│   移项:                                                             │
│   r₁·(v₃' - v₃) + r₂·(v₇' - v₇) = 0                               │
│                                                                     │
│   代入数值:                                                         │
│   r₁·(100 - 80) + r₂·(50 - 70) = 0                                 │
│   r₁·20 - r₂·20 = 0                                                │
│   r₁ = r₂                                                           │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Schwartz-Zippel 引理                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   定理陈述:                                                         │
│   ──────────                                                        │
│   设 P(x₁, x₂, ..., xₖ) 是域 F 上的非零多项式，总次数为 d。       │
│   如果 x₁, x₂, ..., xₖ 从 F 中均匀随机选取，则                    │
│                                                                     │
│               Pr[P(x₁, x₂, ..., xₖ) = 0] ≤ d / |F|                 │
│                                                                     │
│   直观理解:                                                         │
│   ──────────                                                        │
│   一个非零多项式的"零点"只占整个域的很小一部分。                   │
│   随机选取的点落在零点上的概率很低。                                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    将引理应用到批量证明                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   定义多项式（以 r₁, r₂ 为变量）:                                  │
│   ────────────────────────────────                                  │
│                                                                     │
│   P(r₁, r₂) = r₁·(v₃' - v₃) + r₂·(v₇' - v₇)                       │
│                                                                     │
│   其中:                                                             │
│   • v₃, v₇, v₃', v₇' 都是固定常数（不是变量）                     │
│   • r₁, r₂ 是随机变量                                              │
│                                                                     │
│   令 Δ₃ = v₃' - v₃，Δ₇ = v₇' - v₇，则:                           │
│   P(r₁, r₂) = Δ₃·r₁ + Δ₇·r₂                                       │
│                                                                     │
│   分析:                                                             │
│   ──────                                                            │
│   情况 1: 如果 (v₃', v₇') = (v₃, v₇)                               │
│           则 Δ₃ = 0, Δ₇ = 0                                        │
│           P 是零多项式，P(r₁, r₂) = 0 恒成立                       │
│           → 没有伪造，验证自然通过                                  │
│                                                                     │
│   情况 2: 如果 (v₃', v₇') ≠ (v₃, v₇)                               │
│           则 Δ₃ ≠ 0 或 Δ₇ ≠ 0（至少一个非零）                     │
│           P 是非零多项式（一次多项式）                              │
│           → 需要分析 P = 0 的概率                                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    概率计算                                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   假设存在伪造 (Δ₃ ≠ 0 或 Δ₇ ≠ 0):                                │
│                                                                     │
│   P(r₁, r₂) = Δ₃·r₁ + Δ₇·r₂                                       │
│                                                                     │
│   情况 2a: Δ₃ ≠ 0                                                  │
│   ────────────────                                                  │
│   对于任意固定的 r₂，P = 0 意味着:                                 │
│   r₁ = -Δ₇·r₂ / Δ₃                                                 │
│                                                                     │
│   r₁ 有 q 种可能取值（q ≈ 2²⁵⁶）                                   │
│   只有 1 种取值使 P = 0                                            │
│   概率 = 1/q ≈ 1/2²⁵⁶                                              │
│                                                                     │
│   情况 2b: Δ₃ = 0, Δ₇ ≠ 0                                          │
│   ────────────────────────                                          │
│   P(r₁, r₂) = Δ₇·r₂                                                │
│   P = 0 当且仅当 r₂ = 0                                            │
│   概率 = 1/q ≈ 1/2²⁵⁶                                              │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   结论:                                                     │  │
│   │   ──────                                                    │  │
│   │   如果攻击者伪造了任何一个值（v₃' ≠ v₃ 或 v₇' ≠ v₇）        │  │
│   │   攻击成功的概率 ≤ 1/2²⁵⁶                                   │  │
│   │                                                             │  │
│   │   这个概率小到可以忽略不计:                                 │  │
│   │   • 比中彩票概率低 10⁶⁰ 倍                                  │  │
│   │   • 比宇宙中原子数的倒数还小                                │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    推广到 k 个位置                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   如果同时验证 k 个位置:                                           │
│                                                                     │
│   P(r₁, r₂, ..., rₖ) = Σᵢ rᵢ·(vᵢ' - vᵢ) = Σᵢ rᵢ·Δᵢ               │
│                                                                     │
│   只要存在至少一个 Δᵢ ≠ 0:                                        │
│   • P 是非零多项式                                                 │
│   • 总次数 d = 1（每个变量的次数都是 1）                           │
│   • 根据 Schwartz-Zippel: Pr[P = 0] ≤ 1/|F| ≈ 1/2²⁵⁶              │
│                                                                     │
│   注意: 即使 k 很大（比如 1000 个位置），概率仍然是 1/2²⁵⁶        │
│   因为多项式的次数始终是 1，与 k 无关!                             │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**时序很关键：随机数必须在承诺之后生成**

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Fiat-Shamir 变换保证随机性                        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   正确的时序:                                                       │
│   ─────────────                                                     │
│   1. 证明者提交承诺 C（此时已绑定所有值）                          │
│   2. 由 C 的哈希确定随机数: r = H(C, context)                      │
│   3. 用 r 构造聚合选择器                                           │
│   4. 生成并验证聚合 IPA 证明                                       │
│                                                                     │
│   为什么这样安全？                                                  │
│   ────────────────                                                  │
│   • 证明者在步骤 1 时不知道 r 会是什么                             │
│   • r 由 C 确定后，证明者无法修改 C（会改变 r）                    │
│   • 这形成了"先承诺，后挑战"的安全模式                             │
│                                                                     │
│   如果顺序错误（先知道 r，再提交 C）:                              │
│   ─────────────────────────────────────                             │
│   攻击者可以精心构造值，使得伪造的值恰好通过验证                    │
│   例如: 选择 v₃' = v₃ + r₂/r₁ · δ, v₇' = v₇ - δ                   │
│   这样 r₁·v₃' + r₂·v₇' = r₁·v₃ + r₂·v₇ ✓                          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

> 💡 **总结**：随机线性组合的作用是让攻击者无法预测"考试题目"。承诺就像交卷，随机数就像随机抽题验证——交卷后才知道验证哪些题，想作弊就必须每道题都做对。

## 第五章：IPA 的数学原理

### 5.1 问题定义

IPA 要解决的问题：

**已知**：
- 承诺 \( C = \langle \mathbf{v}, \mathbf{G} \rangle = \sum_i v_i \cdot G_i \)
- 选择器向量 \( \mathbf{e} \)
- 声称的内积值 \( z = \langle \mathbf{v}, \mathbf{e} \rangle \)

**目标**：用一个紧凑的证明让验证者相信上述关系成立。

### 5.1.1 IPA 的公共参数：为什么是 O(n)

IPA 需要 O(n) 大小的公共参数，这与 Merkle Tree 的 O(1) 公共参数形成对比。

### 5.2 核心思想：递归折叠

IPA 的精妙之处在于**折叠**：每一轮将问题规模减半，同时保持可验证性。

```
┌─────────────────────────────────────────────────────────────────────┐
│                    IPA 折叠过程 (n = 8 示例)                         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   Round 0: 原始向量 (长度 8)                                        │
│            v = [v₀, v₁, v₂, v₃, v₄, v₅, v₆, v₇]                    │

│                          ▼ 计算交叉项                               │

### 5.3 挑战值 x 的计算：Fiat-Shamir 变换

挑战值 \( x \) 是 IPA 安全性的核心。它必须满足两个条件：
1. 证明者在发送 \( L, R \) 之前无法预测 \( x \)
2. 验证者能够独立计算出相同的 \( x \)

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Fiat-Shamir 变换计算 x                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   基本思想:                                                         │
│   ──────────                                                        │
│   将交互式协议转换为非交互式：                                      │
│   用哈希函数代替验证者的随机挑战                                    │
│                                                                     │
│   计算公式:                                                         │
│   ──────────                                                        │
│   在第 i 轮折叠中:                                                 │
│                                                                     │
│   xᵢ = H(transcript || Lᵢ || Rᵢ)                                  │
│                                                                     │
│   其中:                                                             │
│   • H = 密码学哈希函数 (如 SHA256, Blake2)                         │
│   • transcript = 之前所有轮次的累积数据                            │
│   • Lᵢ, Rᵢ = 当前轮次证明者发送的交叉项承诺                       │
│                                                                     │
│   具体实现:                                                         │
│   ──────────                                                        │
│   transcript₀ = H(C || z || e)           // 初始状态               │
│   x₁ = H(transcript₀ || L₁ || R₁)        // 第 1 轮挑战            │
│   transcript₁ = H(transcript₀ || x₁)     // 更新 transcript        │
│   x₂ = H(transcript₁ || L₂ || R₂)        // 第 2 轮挑战            │
│   ...                                                               │
│                                                                     │
│   安全性保证:                                                       │
│   ──────────                                                        │
│   • 证明者必须先发送 Lᵢ, Rᵢ，才能计算 xᵢ                          │
│   • 哈希函数的单向性确保 xᵢ 不可预测                               │
│   • 任何对 Lᵢ 或 Rᵢ 的修改都会导致 xᵢ 完全改变                    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**伪代码实现**：

```python
def compute_challenges(C, z, e, proof_LR_pairs):
    """
    计算每轮的挑战值 x
    
    Args:
        C: 初始承诺
        z: 声称的内积值
        e: 选择器向量
        proof_LR_pairs: 证明中的 [(L₁,R₁), (L₂,R₂), ...] 列表
    
    Returns:
        challenges: [x₁, x₂, ...] 挑战值列表
    """
    # 初始化 transcript
    transcript = H(C || z || serialize(e))
    
    challenges = []
    for (L, R) in proof_LR_pairs:
        # 计算当前轮的挑战
        x = H(transcript || L || R)
        x = bytes_to_scalar(x)  # 转换为域元素
        challenges.append(x)
        
        # 更新 transcript
        transcript = H(transcript || x)
    
    return challenges
```

### 5.4 关键定理：内积的演变

**定理**：折叠后的内积满足确定的递归关系：
\[ \langle \mathbf{v}', \mathbf{e}' \rangle = \langle \mathbf{v}, \mathbf{e} \rangle + x^2 L_z + x^{-2} R_z \]

其中：
- \( L_z = \langle \mathbf{v}_L, \mathbf{e}_R \rangle \) （内积偏移量）
- \( R_z = \langle \mathbf{v}_R, \mathbf{e}_L \rangle \)

**证明**：

\[ \langle \mathbf{v}', \mathbf{e}' \rangle = \langle x \mathbf{v}_L + x^{-1} \mathbf{v}_R, x^{-1} \mathbf{e}_L + x \mathbf{e}_R \rangle \]

展开：
\[ = x \cdot x^{-1} \langle \mathbf{v}_L, \mathbf{e}_L \rangle + x \cdot x \langle \mathbf{v}_L, \mathbf{e}_R \rangle + x^{-1} \cdot x^{-1} \langle \mathbf{v}_R, \mathbf{e}_L \rangle + x^{-1} \cdot x \langle \mathbf{v}_R, \mathbf{e}_R \rangle \]

由于 \( x \cdot x^{-1} = 1 \)：
\[ = \langle \mathbf{v}_L, \mathbf{e}_L \rangle + \langle \mathbf{v}_R, \mathbf{e}_R \rangle + x^2 \langle \mathbf{v}_L, \mathbf{e}_R \rangle + x^{-2} \langle \mathbf{v}_R, \mathbf{e}_L \rangle \]

\[ = z + x^2 L_z + x^{-2} R_z \quad \square \]

### 5.5 完整的验证过程

#### 🔑 核心突破：验证者不需要知道向量 v

这是 IPA 证明大小从 O(n) 降到 O(log n) 的**关键所在**！

```
┌─────────────────────────────────────────────────────────────────────┐
│                    为什么"不需要 v"如此重要？                        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   朴素证明方案:                                                     │
│   ──────────────                                                    │
│   要证明 ⟨v, e⟩ = z，最直接的方法是:                               │
│   • 证明者发送整个向量 v                                           │
│   • 验证者计算 ⟨v, e⟩，检查是否等于 z                              │
│   • 验证者计算 ⟨v, G⟩，检查是否等于 C                              │
│                                                                     │
│   证明大小 = n × 32 bytes = O(n)                                   │
│   对于 n = 256: 256 × 32 = 8,192 bytes                             │
│                                                                     │
│   IPA 方案:                                                         │
│   ──────────                                                        │
│   • 证明者只发送 log₂(n) 对 (L, R) 和一个标量 v_final              │
│   • 验证者不需要知道 v，只需要折叠承诺和公开参数                   │
│   • 通过递归折叠，最终验证单点等式                                  │
│                                                                     │
│   证明大小 = 2 × log₂(n) × 32 + 32 = O(log n)                      │
│   对于 n = 256: 2 × 8 × 32 + 32 = 544 bytes                        │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   对比 (n = 256):                                          │  │
│   │                                                             │  │
│   │   朴素方案:  8,192 bytes  ████████████████████████████████ │  │
│   │   IPA 方案:    544 bytes  ██                                │  │
│   │                                                             │  │
│   │   压缩比: 15:1                                              │  │
│   │                                                             │  │
│   │   对于更大的 n (如 n = 65536):                              │  │
│   │   朴素方案: 2,097,152 bytes (2 MB)                          │  │
│   │   IPA 方案:     1,056 bytes (1 KB)                          │  │
│   │   压缩比: 2000:1 !!!                                        │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
│   关键洞察:                                                         │
│   ──────────                                                        │
│   验证者可以通过折叠 C（承诺）来"追踪" v 的演变，                  │
│   而无需真正知道 v 的值！                                          │
│                                                                     │
│   这是因为:                                                         │
│   • C 和 v 之间的关系 C = ⟨v, G⟩ 是同态的                         │
│   • 对 v 的线性操作可以"映射"到对 C 的相应操作                    │
│   • L, R 编码了"交叉项"，使验证者能追踪折叠过程                   │
│                                                                     │

```

**验证者只需要以下输入**：
- 初始承诺 \( C \)（不是 \( \mathbf{v} \)！）
- 选择器向量 \( \mathbf{e} \)（公开的，验证者可以自己构造）
- 声称的内积值 \( z \)
- 证明 \( \pi = [(L_1, R_1), (L_2, R_2), ..., (L_k, R_k), v_{\text{final}}] \)

```
┌─────────────────────────────────────────────────────────────────────┐
│                    IPA 验证算法                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   输入:                                                             │
│   • C = 初始承诺 (对向量 v 的 Pedersen 向量承诺)                   │
│   • z = 声称的内积值 ⟨v, e⟩                                        │
│   • e = 选择器向量 (公开)                                          │
│   • G = 生成元向量 (公开)                                          │
│   • U = 内积生成元 (公开)                                          │
│   • π = [(L₁,R₁), ..., (Lₖ,Rₖ), v_final]                          │
│                                                                     │
│   验证步骤:                                                         │
│   ──────────                                                        │
│                                                                     │
│   Step 1: 计算所有挑战值                                           │
│   ─────────────────────────                                         │
│   challenges = compute_challenges(C, z, e, [(L₁,R₁), ...])         │
│   得到 [x₁, x₂, ..., xₖ]                                           │
│                                                                     │
│   Step 2: 折叠承诺 C                                               │
│   ───────────────────                                               │
│   C_current = C + z·U       // 将内积值也编码到承诺中              │
│   for i = 1 to k:                                                   │
│       C_current = xᵢ²·Lᵢ + C_current + xᵢ⁻²·Rᵢ                    │
│                                                                     │
│   Step 3: 折叠生成元 G                                             │
│   ───────────────────────                                           │
│   G_current = G             // 初始生成元向量                       │
│   for i = 1 to k:                                                   │
│       n = len(G_current)                                            │
│       G_L = G_current[:n/2]                                         │
│       G_R = G_current[n/2:]                                         │
│       G_current = [xᵢ⁻¹·G_L[j] + xᵢ·G_R[j] for j in range(n/2)]   │
│   G_final = G_current[0]    // 最终只剩一个生成元                  │
│                                                                     │
│   Step 4: 折叠选择器 e                                             │
│   ───────────────────────                                           │
│   e_current = e             // 初始选择器向量                       │
│   for i = 1 to k:                                                   │
│       n = len(e_current)                                            │
│       e_L = e_current[:n/2]                                         │
│       e_R = e_current[n/2:]                                         │
│       e_current = [xᵢ⁻¹·e_L[j] + xᵢ·e_R[j] for j in range(n/2)]   │
│   e_final = e_current[0]    // 最终只剩一个标量                    │
│                                                                     │
│   Step 5: 最终检验                                                 │
│   ─────────────────                                                 │
│   验证: C_current == v_final·G_final + (v_final·e_final)·U         │
│                                                                     │
│   如果等式成立 → 验证通过 ✓                                       │
│   否则 → 验证失败 ✗                                                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**验证算法的伪代码**：

```python
def verify_ipa(C, z, e, G, U, proof):
    """
    验证 IPA 证明
    
    Args:
        C: 初始承诺
        z: 声称的内积值
        e: 选择器向量
        G: 生成元向量
        U: 内积生成元
        proof: (LR_pairs, v_final)
    
    Returns:
        bool: 验证是否通过
    """
    LR_pairs, v_final = proof
    k = len(LR_pairs)
    
    # Step 1: 计算挑战值
    challenges = compute_challenges(C, z, e, LR_pairs)
    
    # Step 2: 折叠承诺
    C_current = C + z * U
    for i, (L, R) in enumerate(LR_pairs):
        x = challenges[i]
        x_inv = mod_inverse(x)
        C_current = (x**2) * L + C_current + (x_inv**2) * R
    
    # Step 3: 折叠生成元
    G_current = G.copy()
    for i in range(k):
        x = challenges[i]
        x_inv = mod_inverse(x)
        n = len(G_current)
        G_L, G_R = G_current[:n//2], G_current[n//2:]
        G_current = [x_inv * G_L[j] + x * G_R[j] for j in range(n//2)]
    G_final = G_current[0]
    
    # Step 4: 折叠选择器
    e_current = e.copy()
    for i in range(k):
        x = challenges[i]
        x_inv = mod_inverse(x)
        n = len(e_current)
        e_L, e_R = e_current[:n//2], e_current[n//2:]
        e_current = [x_inv * e_L[j] + x * e_R[j] for j in range(n//2)]
    e_final = e_current[0]
    
    # Step 5: 最终检验
    expected = v_final * G_final + (v_final * e_final) * U
    return C_current == expected
```

### 5.6 验证正确性的直觉

```
┌─────────────────────────────────────────────────────────────────────┐
│                    为什么验证是正确的？                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   核心洞察: 证明者和验证者对相同的数据进行相同的折叠操作            │
│                                                                     │
│   证明者视角:                                                       │
│   ────────────                                                      │
│   • 知道完整向量 v                                                 │
│   • 计算 L = ⟨v_L, G_R⟩ + ⟨v_L, e_R⟩·U                            │
│   • 计算 R = ⟨v_R, G_L⟩ + ⟨v_R, e_L⟩·U                            │
│   • 用 x 折叠 v: v' = x·v_L + x⁻¹·v_R                             │
│   • 最终得到 v_final                                               │
│                                                                     │
│   验证者视角:                                                       │
│   ────────────                                                      │
│   • 不知道向量 v，只知道承诺 C = ⟨v, G⟩ + z·U                     │
│   • 收到 L, R 后，计算折叠后的承诺:                                │
│     C' = x²·L + C + x⁻²·R                                          │
│   • 同时折叠 G 和 e（这些是公开的）                                │
│   • 最终检验 C_final == v_final·G_final + (v_final·e_final)·U     │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 🔑 L, R 构造的精妙之处：让 C' 的计算与 v 无关

这是 IPA 能够实现 O(log n) 证明大小的**核心秘密**！

```
┌─────────────────────────────────────────────────────────────────────┐
│                    L, R 的构造目标                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   问题:                                                             │
│   ──────                                                            │
│   证明者知道 v，可以计算折叠后的 v' = x·v_L + x⁻¹·v_R              │
│   但验证者不知道 v，如何计算折叠后的 C'？                          │
│                                                                     │
│   如果验证者也需要 v 才能计算 C'，那就要发送整个 v，                │
│   证明大小就变成 O(n) 了!                                          │
│                                                                     │
│   解决方案:                                                         │
│   ──────────                                                        │
│   精心构造 L 和 R，使得验证者只需要 C, L, R, x 就能计算 C'         │
│   完全不需要知道 v 的任何分量!                                      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    数学推导：为什么这样构造 L, R                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   目标:                                                             │
│   ──────                                                            │
│   我们希望 C' = ⟨v', G'⟩ + ⟨v', e'⟩·U                              │
│                                                                     │
│   其中:                                                             │
│   v' = x·v_L + x⁻¹·v_R                                             │
│   G' = x⁻¹·G_L + x·G_R                                             │
│   e' = x⁻¹·e_L + x·e_R                                             │
│                                                                     │
│   展开 ⟨v', G'⟩:                                                   │
│   ──────────────                                                    │
│   ⟨v', G'⟩ = ⟨x·v_L + x⁻¹·v_R, x⁻¹·G_L + x·G_R⟩                   │
│                                                                     │
│   = x·x⁻¹·⟨v_L, G_L⟩ + x·x·⟨v_L, G_R⟩                              │
│     + x⁻¹·x⁻¹·⟨v_R, G_L⟩ + x⁻¹·x·⟨v_R, G_R⟩                        │
│                                                                     │
│   = ⟨v_L, G_L⟩ + ⟨v_R, G_R⟩        ← 这就是原来的 C!              │
│     + x²·⟨v_L, G_R⟩                 ← 这是"左交叉项"               │
│     + x⁻²·⟨v_R, G_L⟩                ← 这是"右交叉项"               │
│                                                                     │
│   同理展开 ⟨v', e'⟩ (内积部分):                                    │
│   ────────────────────────────────                                  │
│   ⟨v', e'⟩ = ⟨v, e⟩ + x²·⟨v_L, e_R⟩ + x⁻²·⟨v_R, e_L⟩              │
│            = z + x²·L_z + x⁻²·R_z                                   │
│                                                                     │
│   因此:                                                             │
│   ──────                                                            │
│   C' = ⟨v', G'⟩ + ⟨v', e'⟩·U                                       │
│                                                                     │
│      = [C + x²·⟨v_L, G_R⟩ + x⁻²·⟨v_R, G_L⟩]                        │
│        + [z + x²·⟨v_L, e_R⟩ + x⁻²·⟨v_R, e_L⟩]·U                    │
│                                                                     │
│      = C + z·U                                                      │
│        + x²·[⟨v_L, G_R⟩ + ⟨v_L, e_R⟩·U]                            │
│        + x⁻²·[⟨v_R, G_L⟩ + ⟨v_R, e_L⟩·U]                           │
│                                                                     │
│      = C + z·U + x²·L + x⁻²·R                                       │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   关键发现:                                                 │  │
│   │   ──────────                                                │  │
│   │   如果我们定义:                                             │  │
│   │   L = ⟨v_L, G_R⟩ + ⟨v_L, e_R⟩·U                            │  │
│   │   R = ⟨v_R, G_L⟩ + ⟨v_R, e_L⟩·U                            │  │
│   │                                                             │  │
│   │   那么:                                                     │  │
│   │   C' = (C + z·U) + x²·L + x⁻²·R                            │  │
│   │                                                             │  │
│   │   验证者只需要 C, z, L, R, x 就能计算 C'                   │  │
│   │   完全不需要 v !!!                                         │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    L, R 的作用：预计算"交叉项"                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   直观理解:                                                         │
│   ──────────                                                        │
│                                                                     │
│   折叠操作会产生"交叉项" (v_L 与 G_R 的配对，v_R 与 G_L 的配对)    │
│                                                                     │
│   这些交叉项包含 v 的信息，验证者无法独立计算                       │
│                                                                     │
│   证明者的策略:                                                     │
│   ──────────────                                                    │
│   把交叉项预先计算好，打包成 L 和 R 发送给验证者                   │
│                                                                     │
│   L = "左交叉项的承诺" = ⟨v_L, G_R⟩ + ⟨v_L, e_R⟩·U                │
│   R = "右交叉项的承诺" = ⟨v_R, G_L⟩ + ⟨v_R, e_L⟩·U                │
│                                                                     │
│   有了 L, R，验证者就能：                                          │
│   • 不知道 v_L, v_R 的具体值                                       │
│   • 但能正确计算折叠后的 C'                                        │
│   • 从而追踪 C 在整个折叠过程中的演变                              │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   类比:                                                     │  │
│   │   ──────                                                    │  │
│   │   想象你在跟踪一个黑盒的状态变化                            │  │
│   │   • 你不知道盒子里有什么 (v)                                │  │
│   │   • 但每次状态变化时，有人告诉你变化量 (L, R)               │  │
│   │   • 你可以跟踪盒子的"外部表现" (C) 如何变化                 │  │
│   │   • 最后验证最终状态是否一致                                │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    小结：IPA 证明大小的来源                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   每轮证明者发送:                                                   │
│   • L (1 个群元素, 32 bytes)                                       │
│   • R (1 个群元素, 32 bytes)                                       │
│                                                                     │
│   总共 log₂(n) 轮:                                                 │
│   • 2 × log₂(n) 个群元素                                           │
│   • 最后加上 v_final (1 个标量, 32 bytes)                          │
│                                                                     │
│   证明大小 = 2 × log₂(n) × 32 + 32 = O(log n)                      │
│                                                                     │
│   如果没有 L, R 的精妙构造:                                        │
│   • 验证者需要 v 才能计算 C'                                       │
│   • 证明大小 = n × 32 = O(n)                                       │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   L, R 的构造是 IPA 从 O(n) 降到 O(log n) 的关键!           │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.7 信息量视角：证明中包含了什么？

Merkle Tree 和 IPA 的单点证明都是 O(log n)，而 KZG 却能达到 O(1)。让我们从**信息量**的角度分析证明中包含了什么。

#### 证明中的两类信息

```
┌─────────────────────────────────────────────────────────────────────┐
│                    证明中包含的信息类型                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   证明中的信息可以分为两类:                                        │
│                                                                     │
│   1. 位置/路径信息 (Position/Path Information)                     │
│      ────────────────────────────────────                           │
│      • 指示"我在哪里"                                              │
│      • 理论上只需要 log₂(n) bits 就够了                            │
│                                                                     │
│   2. 验证辅助数据 (Verification Auxiliary Data)                    │
│      ─────────────────────────────────────────                      │
│      • 帮助验证者完成计算                                          │
│      • 验证者用它来"重构"从承诺到特定位置的关系                    │
│      • 这才是决定证明大小的关键!                                   │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   关键洞察:                                                 │  │
│   │                                                             │  │
│   │   证明的大小不是由"需要传递多少信息"决定的，                │  │
│   │   而是由"验证者需要多少辅助数据来完成计算"决定的。          │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 三种方案的信息结构对比

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Merkle Tree 的信息结构                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   验证过程: 从叶子逐层计算到根                                     │
│                                                                     │
│   层 0: h₀ = H(value)                                              │
│   层 1: h₁ = H(sibling₀ || h₀) 或 H(h₀ || sibling₀)               │
│   层 2: h₂ = H(sibling₁ || h₁) 或 H(h₁ || sibling₁)               │
│   ...                                                               │
│   层 k: hₖ = Root                                                   │
│                                                                     │
│   每层需要什么？                                                    │
│   ──────────────                                                    │
│   • 兄弟节点的哈希值 (sibling)                                     │
│   • 位置位 (决定左右顺序)                                          │
│                                                                     │
│   证明内容:                                                         │
│   ──────────                                                        │
│   • log n 个兄弟哈希 (每个 32 bytes) → 验证辅助数据                │
│   • 位置索引 i (log n bits) → 位置信息                             │
│                                                                     │
│   为什么不能压缩？                                                  │
│   ────────────────                                                  │
│   哈希函数没有代数结构，验证者无法"跳过"中间步骤                   │
│   必须逐层计算，每层都需要完整的兄弟哈希                           │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    IPA 的信息结构                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   验证过程: 逐轮折叠承诺                                           │
│                                                                     │
│   轮 1: C₁ = x₁²L₁ + C₀ + x₁⁻²R₁                                  │
│   轮 2: C₂ = x₂²L₂ + C₁ + x₂⁻²R₂                                  │
│   ...                                                               │
│   轮 k: Cₖ = v_final · G_final + ...                               │
│                                                                     │
│   每轮需要什么？                                                    │
│   ──────────────                                                    │
│   • (L, R) 交叉项承诺，让验证者能计算折叠后的 C                    │
│   • 挑战 x (由 Fiat-Shamir 从 L, R 计算，不需要额外传输)           │
│                                                                     │
│   证明内容:                                                         │
│   ──────────                                                        │
│   • log n 对 (L, R) (每对 64 bytes) → 验证辅助数据                 │
│   • v_final (32 bytes) → 最终标量                                  │
│                                                                     │
│   为什么需要 (L, R)？                                              │
│   ────────────────────                                              │
│   这正是我们在 5.6 节分析的：                                      │
│   L, R 让验证者能计算 C' 而不需要知道 v                            │
│   它们是"交叉项的承诺"，补偿折叠过程中的信息损失                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                    KZG 的信息结构                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   验证过程: 单次配对运算                                           │
│                                                                     │
│   e(C - v·G, G₂) = e(π, [τ - ω^i]·G₂)                              │
│                                                                     │
│   验证只需要什么？                                                  │
│   ────────────────                                                  │
│   • 证明 π (单个群元素, 48 bytes)                                  │
│   • 位置 i 对应的公共参数 (从预存的 O(n) 参数中查找)               │
│                                                                     │
│   证明内容:                                                         │
│   ──────────                                                        │
│   • 商多项式的承诺 π (48 bytes) → 唯一的验证辅助数据               │
│                                                                     │
│   为什么这么小？                                                    │
│   ──────────────                                                    │
│   配对运算 e(·,·) 有特殊的代数性质:                                │
│   • 可以验证乘法关系而不暴露乘数                                   │
│   • 相当于"一步到位"验证整个关系，不需要中间步骤                   │
│   • 但这依赖于 O(n) 的公共参数中预先编码的结构                     │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 信息在哪里？

```
┌─────────────────────────────────────────────────────────────────────┐
│                    信息分布的可视化                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   方案         证明                公共参数              总成本     │
│   ─────────    ─────────────────   ─────────────────     ─────────  │
│                                                                     │
│   Merkle      [████████ log n]    [▪ O(1)]              证明主导  │
│               兄弟哈希链           只有 H                          │
│                                                                     │
│   IPA         [████████ log n]    [██████████ O(n)]     需要两者  │
│               (L,R) 对             n 个生成元                       │
│                                                                     │
│   KZG         [▪ O(1)]            [██████████ O(n)]     参数主导  │
│               单个群元素           n 个幂次生成元                   │
│                                   + 可信设置的 τ                    │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   观察:                                                     │  │
│   │                                                             │  │
│   │   验证辅助数据可以放在两个地方:                             │  │
│   │   1. 证明中 (每次验证都传输)                                │  │
│   │   2. 公共参数中 (预先分发，一次存储多次使用)                │  │
│   │                                                             │  │
│   │   KZG 把更多信息放在公共参数中，所以证明更小                │  │
│   │   Merkle 把所有信息放在证明中，但公共参数最小              │  │
│   │   IPA 在两者之间取得平衡                                   │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 数学结构与证明压缩

```
┌─────────────────────────────────────────────────────────────────────┐
│                    数学结构决定压缩能力                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   哈希函数 (Merkle):                                               │
│   ────────────────────                                              │
│   • 没有代数结构                                                   │
│   • H(a || b) 与 a, b 之间没有可利用的关系                        │
│   • 验证必须"重走"整条路径                                        │
│   • 无法压缩                                                       │
│                                                                     │
│   向量承诺 + 内积 (IPA):                                           │
│   ────────────────────────                                          │
│   • 有线性结构: C = Σᵢ vᵢ·Gᵢ                                      │
│   • 折叠操作保持同态性: C' = x²L + C + x⁻²R                       │
│   • 可以逐步压缩，但每步需要辅助数据 (L, R)                        │
│   • 压缩率: O(n) → O(log n)                                        │
│                                                                     │
│   多项式承诺 + 配对 (KZG):                                         │
│   ────────────────────────                                          │
│   • 有丰富的代数结构: 多项式除法、配对双线性                       │
│   • P(a) = b 可以用 (P(X) - b)/(X - a) 的承诺来证明               │
│   • 配对允许"跨越"验证，不需要中间步骤                             │
│   • 压缩率: O(n) → O(1)，但需要 O(n) 公共参数                     │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   规律:                                                     │  │
│   │   更强的数学结构 = 更强的压缩能力 = 更大的公共参数/可信设置 │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 总结：三种方案的权衡

```
┌─────────────────────────────────────────────────────────────────────┐
│                    完整的权衡对比                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ┌──────────────┬──────────┬──────────────┬──────────┬──────────┐ │
│   │     方案     │ 证明大小 │ 公共参数大小 │ 可信设置 │ 数学结构 │ │
│   ├──────────────┼──────────┼──────────────┼──────────┼──────────┤ │
│   │ Merkle Tree  │ O(log n) │    O(1)      │   不需要 │   弱     │ │
│   │ IPA          │ O(log n) │    O(n)      │   不需要 │   中     │ │
│   │ KZG          │ O(1)     │    O(n)      │   需要   │   强     │ │
│   └──────────────┴──────────┴──────────────┴──────────┴──────────┘ │
│                                                                     │
│   选择哪种方案取决于你的约束:                                      │
│   ─────────────────────────────                                     │
│   • 要求最小公共参数？ → Merkle                                    │
│   • 要求最小证明且接受可信设置？ → KZG                             │
│   • 要求小证明但不要可信设置？ → IPA                               │
│   • 要求批量证明聚合？ → IPA 或 KZG                                │
│   • 要求抗量子？ → Merkle (换用后量子哈希) 或 IPA (换用后量子群)  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

> 💡 **总结**：证明大小由**"验证者需要多少辅助数据"**决定，而不是由**"需要传递多少信息"**决定。更强的数学结构（如配对）允许更高效的验证，从而减少辅助数据需求。但这种效率不是免费的——它要么需要更大的公共参数，要么需要可信设置。

```
┌─────────────────────────────────────────────────────────────────────┐
│                    例外情况：可信设置方案                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   如果允许可信设置 (Trusted Setup)，可以突破 O(log n) 的限制!      │
│                                                                     │
│   KZG 多项式承诺:                                                   │
│   ─────────────────                                                 │
│   • 承诺大小: O(1) = 48 bytes                                      │
│   • 单点证明大小: O(1) = 48 bytes !!!                              │
│   • 验证时间: O(1)                                                 │
│                                                                     │
│   代价:                                                             │
│   ──────                                                            │
│   • 需要可信设置仪式 (trusted setup ceremony)                      │
│   • 公共参数大小为 O(n)                                            │
│   • 复杂度被"转移"到了公共参数中                                   │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   信息论的守恒定律:                                         │  │
│   │                                                             │  │
│   │   方案           证明大小    公共参数大小    可信设置        │  │
│   │   ─────────────  ──────────  ────────────    ────────        │  │
│   │   Merkle Tree    O(log n)   O(1)            不需要          │  │
│   │   IPA            O(log n)   O(n)            不需要          │  │
│   │   KZG            O(1)       O(n)            需要            │  │
│   │                                                             │  │
│   │   没有免费的午餐!                                           │  │
│   │   O(1) 证明的代价是可信设置或更大的公共参数                 │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
│   以太坊选择 IPA 而非 KZG 的原因:                                  │
│   ─────────────────────────────────                                 │
│   1. 无需可信设置 (transparent)                                    │
│   2. 抗量子攻击的升级路径更简单                                    │
│   3. 批量证明场景下 IPA 聚合效果足够好                             │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

> 💡 **总结**：从信息论角度看，在无可信设置的约束下，O(log n) 是单点证明大小的**理论最优下界**。Merkle Tree 和 IPA 都达到了这个最优值，只是常数因子不同。IPA 的真正优势不在于单点证明，而在于**批量证明的聚合能力**——这是 Merkle Tree 无法做到的。

## 第六章：Verkle Tree 的完整架构

### 6.1 整体结构

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Verkle Tree 架构                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   特点:                                                             │
│   • 分支因子: 256 (每个节点最多 256 个子节点)                       │
│   • 承诺方案: Pedersen 向量承诺 (而非哈希)                          │
│   • 位置证明: IPA (而非 Merkle 路径)                                │
│                                                                     │
│   结构示意:                                                         │
│                                                                     │
│                         [Root Commitment]                           │
│                    C = ⟨children, G⟩                                │
│                              │                                      │
│         ┌───────────────────┼───────────────────┐                  │
│         │         │         │         │         │                  │
│         ▼         ▼         ▼         ▼         ▼                  │
│       [C₀]      [C₁]      [C₂]  ... [C₂₅₄]   [C₂₅₅]                │
│         │                   │                                       │
│    ┌────┴────┐         ┌────┴────┐                                 │
│    │    │    │         │    │    │                                 │
│    ▼    ▼    ▼         ▼    ▼    ▼                                 │
│  [...] [...] [...]   [...] [...] [...]                              │
│                                                                     │
│   树深度: log₂₅₆(状态数) ≈ 3-4 层 (对于 ~10⁸ 状态)                 │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.2 证明一条路径

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Verkle 路径证明                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   要证明某个叶子值，需要证明从根到叶的路径:                         │
│                                                                     │
│   Layer 0 (根):     C_root                                          │
│                        │                                            │
│                   位置 i₀ = 42                                      │
│                        ▼                                            │
│   Layer 1:          C₁                                              │
│                        │                                            │
│                   位置 i₁ = 137                                     │
│                        ▼                                            │
│   Layer 2:          C₂                                              │
│                        │                                            │
│                   位置 i₂ = 88                                      │
│                        ▼                                            │
│   Layer 3 (叶):    leaf_value                                       │
│                                                                     │
│   每层都需要证明:                                                   │
│   "承诺 Cₖ 在位置 iₖ 的值是 Cₖ₊₁ (或 leaf_value)"                  │
│                                                                     │
│   使用 IPA 多点聚合:                                                │
│   所有层的证明可以聚合成一个紧凑的 IPA 证明!                        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.3 为什么不用"每节点一个二叉 Merkle"？

```
┌─────────────────────────────────────────────────────────────────────┐
│                    方案对比: 嵌套二叉 Merkle vs IPA                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   方案 A: 每个 256-ary 节点用一个二叉 Merkle Tree                   │
│   ─────────────────────────────────────────────                     │
│                                                                     │
│   • 单层单证明: 8 × 32 = 256 B                  ← 单证明最优!       │
│   • 单层 k 证明: k × 256 B (无法聚合)                               │
│   • 3 层路径: 3 × 256 = 768 B                                      │
│   • 跨层聚合: 不支持                                                │
│                                                                     │
│   方案 B: 每个节点用 IPA (Verkle 方案)                              │
│   ─────────────────────────────────────                             │
│                                                                     │
│   • 单层单证明: 544 B                                               │
│   • 单层 k 证明: 544 + (k-1)×32 B (可聚合!)                        │
│   • 3 层路径: 可跨层聚合                                            │
│   • 跨层聚合: 支持!                                                 │
│                                                                     │
│   ┌─────────────────────────────────────────────────────────────┐  │
│   │                                                             │  │
│   │   关键差异:                                                 │  │
│   │                                                             │  │
│   │   Merkle: 每个证明独立，无法聚合                            │  │
│   │   IPA:    多个证明可聚合为一个，跨层也可聚合                │  │
│   │                                                             │  │
│   │   在访问 1000+ 个状态的区块中:                              │  │
│   │   • 嵌套 Merkle: 200-500 KB                                 │  │
│   │   • Verkle + IPA: 100-200 KB                                │  │
│   │                                                             │  │
│   └─────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.4 其他优势

除了批量证明更小，IPA 还有以下优势：

| 特性 | 嵌套二叉 Merkle | Verkle + IPA |
|------|-----------------|--------------|
| 承诺更新 | O(log n) 哈希 | O(1) 群运算 |
| SNARK 友好 | ✗ 哈希昂贵 | ✓ 椭圆曲线友好 |
| 可信设置 | 不需要 | 不需要 (IPA) |
| 后量子升级 | 需要换哈希 | 可换底层承诺 |

## 总结与展望

### 核心观点回顾

```
┌─────────────────────────────────────────────────────────────────────┐
│                    从承诺到 Verkle Tree 的演进                       │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   1. 单值承诺                                                       │
│      ───────────                                                    │
│      Hash vs Pedersen: 大小相同，但 Pedersen 有同态性               │
│                                                                     │
│   2. 向量承诺                                                       │
│      ───────────                                                    │
│      Merkle Tree vs Pedersen 向量承诺:                              │
│      • 单证明: Merkle 更小 (256 B vs 544 B)                        │
│      • 批量证明: IPA 可聚合，远小于独立 Merkle 证明之和             │
│                                                                     │
│   3. 位置证明                                                       │
│      ───────────                                                    │
│      • Merkle: 路径上兄弟哈希                                       │
│      • IPA: 将位置证明转化为内积证明，支持聚合                      │
│                                                                     │
│   4. Verkle Tree                                                    │
│      ─────────────                                                  │
│      • 结合高分支因子 (256) 和 IPA 证明                             │
│      • 在真实场景 (批量证明) 中达到最优                             │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 关键公式

| 概念 | 公式 |
|------|------|
| Pedersen 向量承诺 | \( C = \sum_i v_i \cdot G_i \) |
| 位置证明转内积 | \( \langle \mathbf{v}, \mathbf{e}_i \rangle = v_i \) |
| IPA 折叠 | \( \mathbf{v}' = x \cdot \mathbf{v}_L + x^{-1} \cdot \mathbf{v}_R \) |
| 内积演变 | \( z' = z + x^2 L_z + x^{-2} R_z \) |
| Merkle 单证明 (n=256) | \( 8 \times 32 = 256 \) bytes |
| IPA 单证明 (n=256) | \( 16 \times 32 + 32 = 544 \) bytes |
| IPA 批量证明 (k 个) | \( \approx 544 + k \times 32 \) bytes |

### 最终结论

> **对于单个证明，二叉 Merkle Tree 是最优的。但对于以太坊这样需要同时验证上千个状态的系统，IPA 的聚合能力使 Verkle Tree 成为最佳选择。**

这就是为什么以太坊选择了 Verkle Tree + IPA，而不是简单地在每个节点上使用二叉 Merkle Tree。
